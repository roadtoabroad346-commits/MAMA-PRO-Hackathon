Контроль файлов: [manifest](release/manifest.json), [build SHA-256](release/build.sha256).

## Устройство, масштаб, вкладки и ответственный

- Оператор показа: участник команды, запускающий комплект на своём ноутбуке.
  Технический резерв: владелец репозитория. Имена и контакт команды не предоставлены;
  на репетиции команда закрепляет эти роли за людьми. Исполнитель проверок комплекта — Codex.
- Ноутбук с Node 24.22.1, Chromium/Chrome, питание и доступ к локальным файлам.
  Проверено в Linux Chromium 156, эмуляция touch/mobile **390×844**; видео **430×960**,
  содержимое 390×844 вписано с полями. Физическое устройство не проверено.
- Browser zoom **100%** для показа. Мобильный viewport 390×844 можно включить в DevTools;
  это инструмент демонстратора. На проекторе проверить читаемость заранее.
- Одна вкладка приложения, одна вкладка инструкции, резервное видео открыто в локальном плеере.
  Закрыть остальные вкладки приложения перед reset; сравнение находится в памяти конкретной вкладки.
- Использовать один адрес **http://127.0.0.1:5173/**. `localhost`, другой порт, профиль
  или hosted URL имеют отдельные хранилища и не показывают сохранённые здесь requests.

## Подготовка и первый запуск

Из корня распакованного комплекта выполнить `node scripts/serve-release.mjs`.
Ожидается `Production dist: http://127.0.0.1:5173`. Если dist отсутствует, выполнить
`npm ci`, `npm run check`, `npm run build` по [README](../README.md).
Сервер не скачивает зависимости, ничего не публикует. Ctrl+C завершает его.
Если порт занят, завершить прежний экземпляр; смену порта считать новым origin и повторить reset/прогон.

Открыть `/`, дождаться шапки «Демо» и кнопок «Помогите начать» / «Я знаю, кого ищу».
В чистом профиле выбран RU. Нейтральный каталог `/specialists` показывает 12 специалистов;
`/compare` пуст. Прямой `/specialists/S01?offer=O01` показывает O01/S01.
Обновить профиль и убедиться, что он сохранился. Вернуться на `/`.

## Данные и полный reset

Каталог **catalog-v1**, правила **rules-v1**, fixed demoClock
**2026-11-14T12:00:00+05:00**. 12 специалистов, 20 услуг, все вымышлены.
Пропуски ID O19–O22 намеренны. Runtime-генераторов каталога нет.
Синтетические даты не являются датами реальной проверки специалистов.

1. Закрыть все вкладки приложения, кроме одной.
2. Открыть `/privacy`, нажать «Очистить демозапросы на этом устройстве»,
   затем «Удалить демозапросы»; дождаться «Локальные демозапросы удалены.».
   На KK: «Осы құрылғыдағы демосұрауларды тазалау» → «Демосұрауларды жою».
3. В консоли DevTools текущего origin выполнить:

   ```js
   sessionStorage.removeItem('qoldau.demo-search');
   sessionStorage.removeItem('qoldau.demo-request-attempt');
   localStorage.removeItem('qoldau.locale');
   location.replace('/');
   ```

4. Проверить RU, 12 нейтральных специалистов, пустое сравнение. Старый URL request status
   показывает «Демозапрос не найден на этом устройстве». Для KK нажать «Қаз» после reset.
5. Перед **каждым** A/B/C повторять reset. Не переносить возраст/категорию из A в B/C.

Удаление requests подтверждено только после сообщения успеха. При ошибке повторить очистку
или использовать новый отдельный профиль браузера. После перезапуска создаётся новый пустой
search snapshot — наличие ключа `qoldau.demo-search` само по себе не означает старые параметры.

## Последовательность A — основной показ

1. После reset: «Помогите начать». Тема «Речь и общение» → «Далее».
2. Возраст «3–5 лет» → «Далее».
3. «Казахский», «Очно», оба «Это обязательное условие» включены → «Далее».
4. Бостандыкский район, бюджет `6000`; обязательность бюджета и района выключена.
   Предпочтение готовности к обращению включено. Перейти к проверке параметров.
5. Прочитать review, затем «Показать варианты». Точный порядок:
   **S01/O01 → S03/O03 → S02/O02 → S11/O11 → S10/O10**.
   Баллы **100 / 85 / 82.5 / 80 / 75**. Отдельно для уточнения **S07/O07, S08/O08**.
6. Открыть O01/S01, показать выбранную услугу и паспорт: «документ просмотрен»
   не подтверждает подлинность и не гарантирует результат. Нажать «Сравнить».
7. «Вернуться к выдаче», открыть O03/S03, нажать «Сравнить», «Открыть сравнение · 2/3».
   Сравниваются **S01/O01 и S03/O03**, без подмены услуги.
8. В карточке S03 выбрать «Выбрать эту услугу» → **/request/O03**.
   Checkbox понимания деморежима первоначально пуст; без него сохранение недоступно.
9. Отметить checkbox → «Сохранить демозапрос».
   Финал: **S03/O03, catalog-v1, recorded_demo**, фразы
   «Специалисту ничего не отправлено», «Реальная запись не создана».
10. Прочитать созданный request ID, обновить страницу: **тот же ID** и статус.
    Дополнительно: «Отменить демозапрос» → подтвердить → reload;
    статус **cancelled_demo**. Отмена не уведомляет специалиста.

UUID request ID и время создаются в runtime, точное значение заранее не обещать.
Фиксированы ID специалистов и услуг. ID из протоколов/видео не существуют в новом профиле.
Если времени мало, после явного объявления можно начать с прямого профиля S01/O01;
это сокращённый сценарий, а не доказательство нового ввода анкеты.

## Fallback и видеозапись

1. **Hosted: NOT CONFIGURED.** Готовый URL не предоставлен, публикация не поручена.
   Если команда позже предоставляет готовое размещение, сначала сравнить build-хеши,
   проверить deep links/reload/reset на нём; иначе считать его непроверенным.
2. **Локальный резерв: PASS.** `dist` и Node-сервер проверены отдельно без зависимостей,
   включая прямой профиль, reload, реальный IndexedDB save и чтение status.
   Перед показом распаковать архив на ноутбук; internet для запуска готового dist не нужен.
3. **Видео: PASS.** Реально записанные автоматические прогоны A RU/KK:
   [RU, 12.76 сек](release/video/demo-A-ru.webm), [KK, 12.68 сек](release/video/demo-A-kk.webm).
   Chromium, тот же dist, mobile, без озвучки; быстрый технический прогон, можно ставить на паузу.
   Это запись работающего приложения, не интерактивная сессия и не запись человека/родителя.
   В кадре только A до status/reload; B/C и отмена подтверждены тестами, не этим видео.
   Файлы полностью декодированы ffmpeg, [протокол](release/video-check.json).

При переключении сказать: «Сейчас покажу запись того же локального прототипа».
Не объявлять скриншот приложением или старый request ID существующей записью в текущем браузере.

Для повторной записи: выполнить reset, включить захват окна браузера 390×844/100%,
сказать «синтетическое демо», выполнить A шаги 1–10, задержаться на review, compare и status,
показать reload с тем же ID, остановить запись и проверить воспроизведение.
Для автоматической записи после установки тестового FFmpeg:

```sh
RECORD_DEMO=1 PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run check:release -- p0.spec.ts --grep 'P0 A' --workers=1 --reporter=line --output=work/recording
```

`npx playwright install ffmpeg` в текущей среде заблокирован политикой доменов;
фактическая запись выполнена установленным `/usr/bin/ffmpeg` через локальный путь Playwright
`PLAYWRIGHT_BROWSERS_PATH=work/phase13/browsers` и symlink
`work/phase13/browsers/ffmpeg-1013/ffmpeg-linux`. Это зависимость инструмента записи,
не пользовательского приложения. Для новой установки пользоваться доступным официальным
FFmpeg/Playwright или системной записью экрана; готовые видео уже включены в комплект.

## Когда остановить показ

При storage error не заявлять успешное сохранение: повторить проверку либо показать видео.
При несовпадении ожидаемых ID сначала reset и сверка build-хешей; не исправлять каталог перед защитой.
Screen reader, реальные zoom/device-проверки, KK-редактура и понимание родителем остаются NOT RUN.
Ограничения и полный вердикт — [RELEASE_CHECKLIST](RELEASE_CHECKLIST.md),
исторический QA — [QA_RESULTS](QA_RESULTS.md). Полную приёмку P0 и live-работу не заявлять.
