## С чего начать

До кода: отдельная команда пользователя на следующую фазу; для работы до офлайн-этапа — ответ организатора Q-01 о конкретных наработках. Получить состав команды Q-02. Первое техническое действие затем — W-01: закрепить DTO, однозначные правила и oracle A/B/C, включая коррекцию O10. Не начинать с декоративного каталога или облачного backend.

Выбранный минимальный стек для пустого репозитория: React + TypeScript strict + Vite, обычный CSS, один router, typed dictionaries ru/kk, локальные fixtures и IndexedDB. Pure domain не импортирует React/storage/router. UI получает результаты одного SearchService; data-адаптеры изолируют статический каталог и демозапросы. Версии/команды пока не подтверждены manifest; установить их можно только в будущей разрешённой фазе с lockfile. Переписывание существующего приложения не предлагается.

Разделы будущего проекта: `src/app`, `features/intake|search|specialist|compare|request`, `domain`, `data`, `i18n`, `ui`, `tests`. Это ориентир, а не созданные каталоги. Не вводить несколько state libraries, генератор API, DI-фреймворк и серверный стек для локального сценария.

## Временной план мероприятия и ограничения

Расписание из снимка вложений, актуальность требует Q-07. 14 ноября 10:00–18:00 по Алматы (UTC+5; совпадает с Asia/Qyzylorda пользователя). 15 ноября сбор 10:00, защита с 10:30; не считать это вторым днём разработки.

До 13 ноября в рамках допустимой подготовки: Q-01/Q-02/Q-03/Q-04, чтение/документация, распределение ролей, инвентарь происхождения и раскрытие материалов командой. Не закладывать скрытый готовый продукт и не считать уже созданные документы одобренными организатором.

План для трёх опытных участников — цель с риском верхней оценки: 10:00–10:30 сверка условий/контрактов; до 12:00 W-02/W-03 + первые правила; 12:00 checkpoint раннего save/read-back, перерыв; до 13:30 поиск/профиль/compare; около 13:30 короткий тест родителя; 14:30 freeze; до 16:00 исправления, reload/ошибки/RU/KK; до 17:00 сборка/резерв/видео; 17:00–18:00 репетиции/сдача/резерв. Это расписание не доказывает выполнение 28.5 чел.-ч за 24 человеко-часа присутствия. Состав и фактический темп должны подтвердить нижнюю оценку.

Для двух участников доступно максимум 16 чел.-ч присутствия до вычета перерывов/коммуникации, что меньше оценки с резервом. Гарантия полного P0 за день не даётся. Минимальное согласованное действие: добавить согласованный ресурс/время или получить решение о допустимой подготовке; сократить визуальный объём/число уникальных layouts, сохраняя все AC. Если всё равно не помещается, честно отметить незавершённые P0-требования; P0 не переопределять как один каталог.

Checkpoint failures: к 12:00 нет реального save/read-back — сосредоточить интеграцию на W-03/W-08; к 14:30 нет compare→offer→request — прекратить декоративную работу; к 16:30 нет стабильного публичного размещения — использовать проверенную локальную production-сборку, не обещая hosting. Сначала исключаются P1/украшения; unknown, same-offer, RU/KK, честное сохранение и обработка ошибок не вырезаются. 15 ноября до 10:30 только контрольный прогон/оборудование; крупные изменения требуют повторной проверки.

## Финальная проверка и условие остановки

Во время реализации: domain unit для правил/границ/reasons/stable ties; storage integration для commit/abort/idempotency/cancel; integration для draft/applied/selected offer; mobile e2e A на RU и KK, B/C, язык/Back/reload/limit/storage failure. Vitest подходит для domain; Playwright для браузерного пути при доступном окружении. Если автоматика недоступна, зафиксировать ограничение и воспроизводимый ручной протокол, не заявлять e2e PASS. Live/RLS/server access tests вне P0 и не нужны как зависимость demo.

Manual: клавиатура, screen reader smoke, 200% zoom/reflow320, 360/390/430, длинные KK, focus/диалоги/safe-area; проверка носителем и родителем отдельно от автотестов. Performance — лабораторный протокол с устройством/версией/viewport/условиями; цели §19 ТЗ не объявлять измеренными Core Web Vitals. Для фильтрации 100 varied queries на согласованном устройстве, целевой p95≤100ms после load; field p75 без реальных данных не заявлять.

Go для P0: реализованы все P0-строки матрицы, A/B/C RU/KK проверены, нет blocker и major основного пути, selected offer неизменен, commit/отмена/reload/error подтверждены, тексты честны, build воспроизводим, резерв проверен, фактические наблюдения записаны. Родительская/KK-проверка при отсутствии остаются явно незавершёнными. Фаза 0 сама по себе этого статуса не даёт.

После зелёного P0 — зафиксировать доказательства и ограничения, репетировать и остановиться. P1/P2, реальные данные и размещение не запускаются автоматически. Показ доработки 3 декабря и бюджет 300000 ₸ остаются отдельным будущим планом из ТЗ, а не задачами этой фазы.
