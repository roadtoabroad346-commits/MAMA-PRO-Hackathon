# Фаза 8 — S06

Дата: 07.11.2026. Основа: `phase-7-search`, `0d3a81f`. Рабочая ветка: `phase-8-profile`. Объём задан прямым запросом пользователя: профиль и паспорт доверия, переключение услуг, сравнение и передача точной услуги к демозапросу. Развёртывание сайта, реальные обращения и полные S07–S09 не выполнялись.

## Реализованное поведение

| Требование | Реализация |
|---|---|
| Публичное представление | Локализованное имя, категории, синтетическая маркировка, нейтральный avatar с текстом об отсутствии фото; длинное имя переносится |
| Выбранная услуга | Все опубликованные услуги специалиста в native radio group. При входе без `offer` — первая по стабильному ID с явным пояснением. Явный неверный ID не заменяется другим |
| Условия | Цена, единица, длительность, дата и актуальность цены; возраст, язык, формат, район, готовность к обращениям и дата обновления. Неполные значения остаются unknown, онлайн-район — N/A |
| Смена услуги | URL и выбранная radio синхронно меняют один объект offer. От него вычисляются условия, explanations, unknowns, паспорт и ссылка демозапроса. Router transitions отключены для локальных маршрутов: отложенный navigation не должен возвращать radio прежнее значение |
| Matching | Использован существующий `SearchService.inspectOffer`, без второй классификации в UI. В selector видны exact/incomplete/incompatible состояния. Несовместимая услуга не сохраняет прежних reasons; неизвестные сведения самой услуги доступны и в этом состоянии |
| Deep links | Без `location.state` перехода из каталога/сравнения профиль нейтрален даже при сохранённых условиях в sessionStorage. Нет персональных reasons. Unknown/hidden/withdrawn/чужая offer недоступны; unknown/hidden профиль не публикуется |
| Подход | Короткие нейтральные синтетические примеры вместо исходной заглушки bio. Они явно названы примерами и сведениями из анкеты; эффективности и результата не обещают. Отсутствующее bio допускается и честно обозначается |
| Паспорт | Отдельные identity, education, contact и offer_data. Для каждого факта — статус, источник, дата, объём, ограничение; для имеющейся проверки — дата пересмотра. Отсутствие факта не превращается в утверждение о достоверности |
| Просмотр документа | DOCUMENT_SEEN остаётся просмотром; отдельно написано, что подлинность у выдавшей организации не подтверждается просмотром. Устаревшие/будущие даты не дают действующий SOURCE_CONFIRMED. REVOKED сохраняется как отзыв |
| Данные услуги | Источники и даты отдельных полей берутся из выбранной offer.fieldSources. Сведения из синтетической анкеты имеют SELF_DECLARED, а не независимое подтверждение. Цена устаревает через 30 дней, сведения об обращениях — через 7, относительно demoClock |
| Проверка конкретной услуги | Дополнительный VerificationFact со scope=offer_data обязан ссылаться на offer того же специалиста. Факт O06 не показывается как проверка O15 |
| Сравнение | Использован существующий список пар: смена radio сама не подменяет закреплённую услугу. Для другой услуги того же специалиста требуется явное действие «Сравнить эту услугу вместо прежней». Работают просмотр сравнения и возврат |
| Демозапрос | `/request/:offerId` повторно проверяет публикацию и принадлежность, показывает резюме той же пары и честное «пока не сохранён». Для несовместимой услуги переход из профиля требует ознакомления с предупреждением. Reload сохраняет offer из URL; возврат открывает ту же услугу |
| Приватность | Нет сканов, номеров документов, служебных заметок, данных проверяющего и настоящего бейджа фонда. Нет реального контакта, сбора имени/телефона/диагноза, внешних запросов и выдуманного успеха сохранения |
| Доступность | Native radio/checkbox/links, выбор стрелками, видимый focus, live-объявление смены услуги без переноса фокуса, возврат к каталогу с исходным scroll/focus. RU/KK, длинные строки, reflow320, текст 200%, landscape и reduced motion |

## Данные и совместимость

В public schema добавлены необязательные `sourceLabel` и `offerId` факта, а также scope `offer_data`; старые записи без новых полей остаются валидными. Без источника/даты исходный статус не повышается до проверенного. `bio` допускает отсутствие. Локальная схема сессии и matching не изменялись.

В синтетическом каталоге S01/S02 получили явное название источника просмотренного документа. Противоречивый S03/UNVERIFIED больше не говорит о состоявшемся просмотре. Нейтральные примеры подхода созданы для демо; это не сведения о реальных специалистах. Исходные документы в `docs/sources` сохранены без изменений.

## Проверки

Команды:

```sh
npm ci
npm run typecheck
npm test
npm run build
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

- TypeScript strict и production build — PASS.
- Unit: **44 PASS**; из них 5 новых проверок resolver, публикации/принадлежности, дат, статусов и scope offer_data.
- E2E: **41 PASS** в заключительном полном прогоне: 28 прежних и 13 профильных сценариев.
- Покрыты несколько услуг, неполный профиль/отсутствующее описание, нет фото, длинное имя, unknown, stale/future/revoked, смена offer/reasons/unknowns, явная замена compare, возврат, reload, RU/KK в одном профиле и keyboard.
- Отдельно проверена production-сборка через Vite preview: `O23 → O24 → /request/O24 → reload → Back → KK`. Запросы только к локальному origin, ошибок JavaScript нет, overflow отсутствует. Браузер отдельно запросил отсутствующий у исходного проекта `/favicon.ico` (404); это не ошибка загрузки каталога или маршрута.
- Мобильный профиль и desktop-паспорт просмотрены по screenshot. Доступность не объявляется полным WCAG-аудитом; тест носителем KK, родительское исследование и ручной screen reader аудит не проводились.
