# S01–S03, фазы 28–35

Переиспользованы фактические компоненты, токены, router и typed dictionaries фаз 6–14. Новая дизайн-система не создаётся. UI/UX Pro Max использован как проверка keyboard/focus, labels/errors, mobile/reflow, основной CTA и reduced motion; доступный cloud quick reference, без утверждения о выполненном локальном database search (scripts/search.py в executor отсутствует). React best practices: чистые updater-функции, derived summary/count, schema storage boundary, без новых библиотек/эффектов синхронизации counts.

S01 `/`: имя, RU/KK, DemoBadge, назначение, небольшой SVG Қарлығаш, «Помогите начать»→`/route`, «Я знаю, кого ищу»→`/specialists`, демо/приватность и отсутствие регистрации. Используется существующий applied поиск; незавершённая анкета автоматически не применяется.

S02 `/route`: четыре шага: тема; возраст; язык/формат; район/бюджет/готовность к обращениям. Не уверен/пропуск сохраняют null; возраст задаётся группой, всегда hard. Язык UI отдельно от языка занятий. Конкретные язык/формат default hard; явные переключатели soft сохранены по существующему контракту. Район soft default; optional hard виден при выбранном активном районе. Для online-only район сохранён, но не участвует в поиске. Бюджет — integer 0…100000, пустое=null. Текстовая невалидная строка остаётся в памяти, inline error связана с полем; submit фокусирует его. Остальные ответы не стираются. Назад/история/смена языка сохраняют шаг и ответы.

S03 `/route/review`: семантический dl из canonical intakeDraft после нормализации SearchService, семь полей/режимов hard/preference/unrestricted/unused; каждый edit возвращает к соответствующему шагу. Дополнительная категория — существующее необязательное уточнение. «Не уверен» не создаёт категорию. Это параметры поиска, не медицинское заключение. Count — тот же SearchResult, который после применения получит каталог. CTA «Показать варианты» валидирует бюджет и фиксирует applied input; уход другим путём его не фиксирует. Invalid budget после Back в review скрывает count и блокирует CTA, даёт ссылку исправления. При нуле нет auto-relax. Direct review без анкеты — нейтральные 12/20.

Loading/error repository: существующий стартовый экран без подмены результатов; Retry повторяет загрузку, сохранённый synthetic session восстанавливает draft/applied. Ноль — успешный SearchResult с count0. Искусственных задержек нет. Guard effect запрещает позднему ответу заменять новый запрос; сам поиск синхронный, без гонок фильтрации.

Память/session: input=applied, intakeDraft отдельный; одна schema SearchInput, optional поле в v1 snapshot. Старый v1 читается с intakeDraft=input. Locale отдельно. TTL2h, несовпадение catalogVersion/ошибка схемы очищает только app key с уведомлением. Invalid budget raw только в памяти. Никаких ответов в URL, логах, внешних API или analytics. Имени ребёнка, даты рождения, диагноза, телефона, файла и свободного медицинского текста нет.

Существующий каталог/профиль/compare/demo requests сохраняются; эта задача не объявляет фазы 36+ завершёнными. Визуальные и runtime-доказательства: docs/phases28-35 и QA_RESULTS. Экспертная редактура KK, реальный родитель и screen reader требуют отдельной проверки.
